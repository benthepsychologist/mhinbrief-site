# AGENTS.md — mhinbrief-site operating disciplines

This repo is the published surface only — a Hugo site plus one Cloudflare
Worker. It has no data of its own; everything a reader sees traces back
to mhinbrief-corpus's records/changelog, rendered here by that repo's
adapter. These are this repo's own numbered disciplines — not kestrel's
engine invariants (this isn't a kestrel-tended instance), just what's
actually true operating in this specific repo.

1. **One content writer, still.** `content/changelog/*.md`,
   `data/records.yaml`, `data/regulators.yaml`, `data/review.yaml` are
   generated by `mhinbrief-corpus/publish/adapter.py` — never hand-edit
   them here. Templates/layouts, CSS, and the hand-authored editorial
   pages (`content/_index.md`, `method.md`, `newsletter.md`, the section
   framing pages) are this repo's own, edited directly.

2. **A git push here deploys nothing.** Deploy is `hugo && wrangler
   deploy`, run explicitly (see README.md/CLAUDE.md — confirmed
   2026-08-12 against Cloudflare's own deployments API, not assumed).
   Landing a commit and having the live site match are two separate
   facts; verify the second by curling mhinbrief.com, not by checking
   git log.

3. **`CLOUDFLARE_API_TOKEN` is required for any deploy or Cloudflare API
   action**, sourced from this repo's gitignored `.env`
   (`set -a && source .env && set +a` — plain `source` alone doesn't
   export to child processes like `wrangler` or `python3`, a real
   trip-up this session). Token scope: Workers Scripts/KV/Access on the
   account, Zone/DNS/Workers Routes/SSL on all zones. No Registrar,
   Billing, or Member-management scope — don't request those for this
   repo's purposes.

4. **`worker/index.js` is the one dynamic route.** Everything except
   `POST /api/feedback` falls through to the static build via the
   `ASSETS` binding. Adding new dynamic behavior means adding a path
   check here, not a second Worker or a Cloudflare Pages Function.

5. **Cloudflare Access gates `/review/` and `/api/feedback` — both,
   separately.** Access scopes strictly by path; protecting one doesn't
   cascade to a sibling path (caught live, 2026-08-12 — the first pass
   only covered `/review`, leaving `/api/feedback` reachable
   unauthenticated). A new protected route needs its own destination
   entry on the Access application, not an assumption of coverage.

6. **A verified identity comes from `worker/access-jwt.js`, never a form
   field.** The `Cf-Access-Jwt-Assertion` header is checked against
   Cloudflare's public keys, the `aud` claim, and expiry before its
   `email` claim is trusted. Don't reintroduce a free-text name field as
   a shortcut — that's exactly the trust model this was built to
   replace.

7. **`MHINBRIEF_DEPLOY_HOOK` is documented legacy, not a live
   mechanism.** Confirmed via Cloudflare's deployments API (2026-08-12):
   every deployment this site has ever had was `source: wrangler`, none
   via a connected build. Don't resurrect "fire the hook" as a deploy
   step without first confirming a Workers Build connection actually
   exists.

8. **`mhinbrief-corpus` is not this repo's jurisdiction, and vice
   versa.** Record/changelog/schema questions belong in the data repo;
   this repo owns its own templates, styling, and Worker code.
